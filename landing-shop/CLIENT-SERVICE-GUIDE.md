# Webzo BD — Client Landing Page Service Workflow

## 1) Client onboarding
Collect: business/brand name, logo, product names, prices, product images, sizes/colors/stock, delivery areas/charges, COD/payment policy, return policy, phone/WhatsApp, Facebook/TikTok links, real reviews, domain, Meta Pixel/GTM/GA4/TikTok IDs.

## 2) Commercial process
Before work: written scope, delivery date, revision count, hosting/domain responsibility, maintenance scope, and payment milestones. Do not promise ad sales/results; sell the build, tracking setup and support you can verify.

## 3) Build process
Duplicate the master folder → open admin.html → fill client data → Save & Preview → test Mobile/Tablet/Desktop → Download config.js → replace the project config.js → add client logo/images → deploy.

## 4) QA before delivery
Test: every gallery image, product/size/quantity, out-of-stock states, delivery charge, totals, phone validation, order submission, thank-you page, WhatsApp links, call links, all social links, 320/360/390/430px mobile widths, desktop, slow mobile loading, Pixel/GA4 events, domain HTTPS.

## 5) Handover
Give client: live URL/domain, order-receiving instructions, tracking IDs used, admin/config backup, basic edit guide, support period and renewal/maintenance terms.

## 6) Reusable service packages
Starter: landing page + mobile responsive + COD form.
Business: Starter + custom domain + WhatsApp + analytics/pixels + conversion events.
Care plan: monthly content/price/stock changes, backups, QA and tracking checks.

## Security note
admin.html is a static local builder, not a password-protected CMS. Use it locally while building. Before client delivery you may delete admin.html/admin.js/admin.css from the deployed folder if the client does not need it. A true online multi-client dashboard requires authentication + database/backend and should be built separately.
