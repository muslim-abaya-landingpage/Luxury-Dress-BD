# WhatsApp অর্ডার OTP ভেরিফিকেশন — সেটআপ গাইড

এই ফিচার (যুক্ত হয়েছে ২০২৬-১১-২১) শুধু তখনই চালু থাকে যখন অর্ডারের **নিজের fraud-risk score** ইতিমধ্যে `review` বা `high` (অর্থাৎ ঝুঁকিপূর্ণ) হয় — বাকি সব সাধারণ অর্ডারের checkout একদম আগের মতোই থাকবে, কোনো এক্সট্রা স্টেপ নেই।

**কোড এখন সম্পূর্ণ রেডি ও টেস্ট করা, কিন্তু নিচের তিনটি জিনিস Cloudflare Worker-এ সেট না করা পর্যন্ত এই ফিচার সম্পূর্ণ বন্ধ থাকবে — ঝুঁকিপূর্ণ অর্ডারও OTP না চেয়ে আগের মতো সরাসরি যাবে।**

## এটা পুরোপুরি ফ্রি নয় — honest হিসাব

- WhatsApp Cloud API নিজে ফ্রি (কোনো মাসিক সাবস্ক্রিপশন ফি নেই)।
- কিন্তু প্রতিটা OTP মেসেজের একটা ছোট খরচ আছে (Authentication template) — বাংলাদেশে প্রায় $0.01-এর আশেপাশে প্রতি মেসেজ (Meta-র রেট কার্ড অনুযায়ী বদলাতে পারে)।
- যেহেতু এটা শুধু ঝুঁকিপূর্ণ অর্ডারে চলবে (বেশিরভাগ অর্ডার না), মোট খরচ খুব কম থাকবে।

## Meta-র সাইডে যা করতে হবে (আপনার নিজের কাজ, কোডের বাইরে)

1. **Meta Developer App তৈরি করুন** — developers.facebook.com-এ গিয়ে একটা App তৈরি করুন, তাতে "WhatsApp" প্রোডাক্ট অ্যাড করুন।
2. **WhatsApp Business Account (WABA) + একটা ফোন নম্বর** — Meta-র WhatsApp Manager থেকে একটা বিজনেস ফোন নম্বর যুক্ত করুন (এটা আপনার পার্সোনাল WhatsApp নম্বর থেকে আলাদা হতে হবে)।
3. **Business Verification** — Meta Business Suite-এ আপনার বিজনেস ভেরিফাই করুন (ট্রেড লাইসেন্স/ডকুমেন্ট লাগতে পারে)। এটা ছাড়া AUTHENTICATION টেমপ্লেট approve হবে না।
4. **একটা permanent Access Token বানান** — "temporary" কুইকস্টার্ট টোকেন ২৪ ঘণ্টায় মেয়াদ শেষ হয়ে যায়, তাই production-এ System User দিয়ে একটা স্থায়ী (permanent) টোকেন বানাতে হবে।
5. **AUTHENTICATION ক্যাটাগরির একটা Message Template বানান** এবং Meta-র approval এর জন্য পাঠান — শুধু BODY আর FOOTER (code expiration) থাকলেই চলবে, বাটন (copy-code/one-tap) ঐচ্ছিক। টেমপ্লেটের নাম যেটা দেবেন সেটাই `WHATSAPP_OTP_TEMPLATE`-এ সেট করতে হবে (ডিফল্ট ধরে রাখা হয়েছে `order_otp`)।
6. **তিনটা জিনিস কপি করে রাখুন**:
   - **Phone Number ID** (⚠️ এটা WABA ID নয় — ভুল করে WABA ID দিলে Meta Error 100 দেখাবে)
   - **Access Token** (স্থায়ী, System User-এর)
   - (ঐচ্ছিক) টেমপ্লেটের নাম ও ভাষা কোড

> **সতর্কতা:** Business Verification ও টেমপ্লেট approval-এ Meta-র পক্ষ থেকে কিছুদিন সময় লাগতে পারে। এটা এই সেশনের নিয়ন্ত্রণে নেই — approval হওয়া পর্যন্ত নিচের সেটিং সেট না করলে ফিচারটা নিরাপদে বন্ধ থাকবে (কোনো অর্ডার আটকাবে না)।

## Cloudflare Worker-এ সেট করুন

Cloudflare Dashboard → Workers → **white-lab-3589** → Settings → Variables and Secrets:

| নাম | ধরন | মান |
|---|---|---|
| `WHATSAPP_ACCESS_TOKEN` | Secret | Meta-র স্থায়ী Access Token |
| `WHATSAPP_PHONE_NUMBER_ID` | Text | Phone Number ID (WABA ID নয়!) |
| `OTP_TOKEN_SECRET` | Secret | ৩২+ র‍্যান্ডম অক্ষরের একটা নিজের পাসওয়ার্ড/কোড (যেকোনো র‍্যান্ডম স্ট্রিং জেনারেটর থেকে বানান) |
| `WHATSAPP_OTP_TEMPLATE` | Text (ঐচ্ছিক) | আপনার টেমপ্লেটের নাম (ডিফল্ট: `order_otp`) |
| `WHATSAPP_OTP_TEMPLATE_LANG` | Text (ঐচ্ছিক) | ভাষা কোড (ডিফল্ট: `bn`) |
| `WHATSAPP_OTP_BUTTON_SUBTYPE` | Text (ঐচ্ছিক) | টেমপ্লেটে copy-code/one-tap বাটন থাকলেই দিন |

তিনটা মূল জিনিস (`WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `OTP_TOKEN_SECRET`) সেট হওয়ার সাথে সাথেই, কোনো নতুন ডিপ্লয় ছাড়াই, ঝুঁকিপূর্ণ অর্ডারে OTP চালু হয়ে যাবে।

## এটা কীভাবে কাজ করে (সংক্ষেপে)

1. একজন কাস্টমার Place Order চাপে। Worker অর্ডারের fraud-risk score হিসাব করে, যেমনটা আগে থেকেই করত।
2. স্কোর `low` হলে — কিছুই বদলায় না, অর্ডার সরাসরি চলে যায়।
3. স্কোর `review`/`high` হলে (এবং উপরের তিনটা সেট করা থাকলে) — অর্ডারটা "awaiting_otp" অবস্থায় সেভ হয়ে থাকে, কাস্টমারের ফোনে একটা ৬ ডিজিটের কোড চাওয়ার মডাল দেখা যায়।
4. কাস্টমার "আবার কোড পাঠান"-এ ক্লিক করলে WhatsApp-এ কোড যায় (৫ মিনিটের মধ্যে ব্যবহার করতে হয়, সর্বোচ্চ ৫ বার ভুল চেষ্টা, ঘণ্টায় সর্বোচ্চ ৫টা কোড)।
5. সঠিক কোড দিলে একটা সাইনড টোকেন পাওয়া যায়, আর অর্ডারটা সেই টোকেন দিয়ে আবার সাবমিট হয়ে Apps Script-এ (শিট-এ) চলে যায় — ঠিক আগের মতোই।

কোনো ধাপে WhatsApp API ফেইল করলে বা কনফিগার করা না থাকলে, সিস্টেম "fail-open" — মানে অর্ডার আটকায় না, শুধু OTP স্টেপটা স্কিপ হয়ে যায়।
